# 地方政府單位預算「歲出計畫說明提要與各項費用明細表」解析工具

把**直轄市／縣（市）政府單位預算案** PDF 中的「歲出計畫說明提要與各項費用明細表」轉成可篩選、檢核及匯出的結構化表格。

> **⚠ 本工具僅供輔助核對，不能取代人工審閱。一切數據以政府公布的預算書 PDF 原文為準。**

本工具採單一 HTML 檔與純前端架構，使用 pdf.js 讀取 PDF；遇到特定內嵌字型無法解讀時，會自動改用 PDFium 後備引擎。使用者選取的 PDF 只在瀏覽器本機處理，**檔案不會上傳至伺服器**。

---

## 主要功能

- 解析地方政府單位預算案 PDF 中的「歲出計畫說明提要與各項費用明細表」。
- 擷取工作計畫、分支計畫、用途別科目及逐筆費用明細。
- 保留單位、數量、單價、預算數及說明文字。
- 依工作計畫、分支計畫、用途別科目、資料層級及說明關鍵字篩選。
- 執行四層加總驗算：
  1. 明細 → 用途別科目
  2. 用途別二級 → 用途別一級
  3. 用途別一級 → 分支計畫
  4. 分支計畫 → 工作計畫
- **工作計畫核對**：以同一本預算書的「歲出機關別預算表」為外部基準，驗工作計畫的編號、名稱與本年度預算數（見下節）。
- 將全期「總工程費／總經費」與本年度預算分開處理，並以案別金額旁的 tooltip 顯示，不另占資料列。
- 對少數欄位黏連情形執行保守式金額修復，並保留原始擷取值供複核。
- 匯出目前篩選結果為 XLSX、CSV 或 JSON。
- 匯出驗算差異及自動修復紀錄。
- 辨識合法千分位金額後黏接的2位數案號，避免 `9,330,000＋01` 被誤建為 `933,000,001`。
- pdf.js 無法解讀內嵌字型時，自動切換 PDFium 後備引擎。

## 與中央版的差異

本工具與 [unit-budget-parser](https://github.com/cormort/unit-budget-parser) 所解析的中央機關「歲出計畫提要及分支計畫概況表」是**不同格式的預算表**，因此獨立建立 repository。

| 比較項目 | 中央機關 | 地方政府 |
|---|---|---|
| 章節名稱 | 歲出計畫提要及分支計畫概況表 | 歲出計畫說明提要與各項費用明細表 |
| 工作計畫代碼 | 10 碼 | **11 碼** |
| 主要欄位 | 金額／承辦單位／說明 | **單位／數量／單價／預算數／說明** |
| 金額單位 | 千元 | **元** |
| 說明文字 | 敘述段落，需以規則鏈推論歸戶 | **逐明細列短語，原則上一對一對應** |
| 頁面兩側 | 無 | **直書標籤**，例如機關名或計畫名逐字直排 |

地方表的說明文字原則上直接綁定各筆明細，因此中央版所使用的名稱與金額配對、加總推論、順序界限、孤兒句及橘底待確認等歸戶規則，在本工具中不需要使用。

## 資料層級

主要資料結構如下：

```text
工作計畫（11 碼）
└─ 分支計畫（2 碼，代碼後直接接名稱）
   └─ 用途別一級（4 碼，末三碼為 000）
      └─ 用途別二級（4 碼）
         └─ 明細列（單位／數量／單價／預算數／說明）
```

### 分支計畫與用途別科目的判別

- 分支計畫：2 碼後直接接名稱，例如 `05會計業務`。
- 用途別科目：4 碼後有空格，例如 `2000 業務費`。
- 用途別一級：4 碼且末三碼為 `000`，例如 `2000 業務費`。
- 用途別二級：其他4碼用途別科目，例如 `2054 一般事務費`。

## 顯示但不納入本年度驗算的層級

除主要資料層級外，工具另保留下列輔助層級供閱讀，但不納入本年度預算明細加總。

### 1. 計畫說明

提要頁所列的計畫預算金額，以及「較上年度預算數……增加／減少……元」等文字，屬於計畫層說明，不是用途別科目下的費用明細。

若誤判為明細，會被錯誤加到上一個科目。早期實測臺中市資料出現的6筆差異，即與此類計畫說明誤入明細有關。

### 2. 案別

工程或資本門型計畫可能在分支計畫之下另設「案」層。此類資料常見特徵如下：

- 左側科目欄空白。
- 只有預算數。
- 案號與名稱寫在說明欄，例如 `03-113年個人電腦租賃費`。
- 案別下方另列一組 `3000 設備及投資`、`3030 資訊軟硬體設備費`等科目。

案別金額通常是其下科目的本年度小計。若將案別當成分支計畫，會在分支加總時重複計入；若將案別當成一般明細，則可能被加到上一個科目。

同一分支計畫下，同一個用途別一級科目可能因不同案件而重複出現，因此驗算用途別一級時，會先依工作計畫、分支計畫及用途別一級代碼組成的 key 累加，再與分支計畫金額比較。

### 3. 總經費 tooltip

跨年度連續性計畫及工程計畫，常在本年度預算明細後另列：

1. 本年度預算數。
2. 「總工程費（或總經費）明細如下」標題列。
3. 全期總工程費或總經費的組成明細。

第2項與第3項是同一全期計畫總額的不同呈現，均不屬於本年度預算明細。若全部納入加總，會造成總經費被重複計入，並使科目驗算失真。

新版解析器會：

- 偵測「總工程費」、「總經費」及「總工程費（或總經費）明細如下」等文字。
- 在內部資料層保留 `總經費` 層級，供驗算、tooltip 組裝及測試使用。
- 將全期總經費及其組成明細附加到所屬 `案別`。
- 在案別的本年度預算數旁顯示紫色 `ⓘ`。
- 滑鼠移到本年度預算數或 `ⓘ` 時，以 tooltip 顯示全期總經費、組成明細及排除提醒。
- 主畫面不再顯示紫色總經費獨立列。
- 不將總經費納入本年度明細合計及四層加總驗算。
- XLSX、CSV及JSON的主要明細不另輸出總經費列，而是在案別列附加「全期總經費」及「總經費說明」欄位。

例如：

```text
本年度預算：1,060,000元 ⓘ
```

tooltip 顯示：

```text
全期總工程費／總經費：6,360,000元
建置老人自費安養中心監視影音系統：6,360,000元
此金額僅供查閱，不納入本年度明細合計及四層驗算。
```

## 版面偵測原則：座標靠量測，不寫死

地方政府預算書來自不同產製系統，即使是同一份 PDF，也可能存在不同表頭、欄寬及文字物件組合。工具以每頁實際文字座標量測欄界，不使用單一組固定座標。

### 表頭可能橫跨兩列

實測臺中市資料中，「分支計畫及用途別科目」位於 `y=732`，其他欄名位於 `y=725`，相差7pt。解析器會抓取表頭中心上下12pt的文字帶，避免只讀到部分欄名。

### 科目欄名可能有兩種寫法

- 首頁：`分支計畫及用途別科目`
- 續頁：`用途別科目`

兩種文字置中後的 x 座標可相差約22pt，因此解析器同時支援兩種欄名。

### 欄界取相鄰欄名的中點

不同欄位的資料對齊方式不同：

- 單位欄通常置中。
- 數量、單價及預算數通常靠右。
- 說明欄通常靠左。

例如實測臺北市資料中：

- 單價欄名約在 x=315，值可能落在 x=320～344。
- 預算數欄名約在 x=390，值可能落在 x=410～427。
- 說明欄名約在 x=484，但說明內文可能從 x=450 開始。

因此不能以欄名加減固定偏移量切欄。工具以相鄰欄名 x 座標的中點建立初始欄界。

### 說明欄左緣使用內文眾數

說明欄欄名通常置中，但內容靠左。解析器會統計資料區中多字元文字物件的 x 座標眾數，推定說明欄左緣。

統計時排除：

- 以數字或逗號開頭的文字物件。
- 單一字元物件。
- 表頭以上的內容。

這可避免下列文字物件干擾：

```text
80,000 購置總預算編製作業手冊……
```

如果把此類「預算數＋說明」的黏連物件一併計入眾數，說明欄左緣可能錯落在金額欄。

### 兩側直書標籤偵測

地方預算書兩側常有逐字直排的機關名或計畫名。其特徵是大量單一字元堆疊在相同 x 座標上。

解析器只在表頭以下的資料區偵測同 x 的單字堆疊，避免將提要頁內層的「歲出計畫說明」等直書標籤誤認為表格邊界。

## 文字與欄位黏連處理

PDF文字擷取不等於表格擷取，同一視覺列在文字層中可能被拆成多個物件，也可能將不同欄位合成一個物件。

### 預算數與說明黏在同一文字物件

解析器支援以下兩種常見形式：

```text
148,000 1.系統維護……
32,000約僱人員休假旅遊補助費。
```

程式會將前段數字拆入預算數欄，其餘文字放入說明欄。

### 說明清單編號落入預算數欄

說明文字中的 `1.`、`2.` 等清單編號可能凸排到說明欄左側，落入預算數欄的座標帶。1至2位數後接句點的文字不可能是預算數，因此會撥回說明欄。

### 公文字號或長數字落入預算數欄

公文字號跨行時，可能出現沒有千分位逗號的長數字，例如：

```text
1130004549號函
```

解析器將預算數欄中5位以上且沒有千分位逗號的長數字視為說明文字，避免誤產生巨額假明細。

### 說明欄大型數字誤判

若某列：

- 沒有科目名稱。
- 沒有單位、數量及單價。
- 只有一個大額數字與說明文字。
- 該數字大於目前用途別科目的表列金額。

解析器會將該列視為說明續行，而不是費用明細。此規則可降低工程說明或全期金額誤入本年度預算數欄的風險。

---

### 千分位金額與2位數案件編號黏連

工程及資本門型計畫的案件列，可能以「本年度預算數＋2位數案號＋案件名稱」呈現，例如：

```text
9,330,000  01-南港社福中心中繼辦公室整修工程
7,808,000  02-民生社區中心中央空調設備汰換暨新設能源管理系統工程分攤款
```

PDF文字物件可能將金額與案號合併為：

```text
9,330,00001
7,808,00002
```

若直接移除逗號轉成數值，會錯誤形成：

```text
933,000,001
780,800,002
```

解析器只在下列條件同時成立時拆分：

1. 前段符合合法千分位金額格式。
2. 金額後接2位數案件編號。
3. 案號介於 `01` 至 `99`。
4. 後續案件名稱以連字號 `-` 或 `–` 開始。
5. 該列沒有單位、數量及單價。

修復後還原為：

```text
預算數：9,330,000
說明：01-南港社福中心中繼辦公室整修工程

預算數：7,808,000
說明：02-民生社區中心中央空調設備汰換暨新設能源管理系統工程分攤款
```

此規則不以「是否為1,000的倍數」判斷一般明細，因為表內金額以元列示，正常明細仍可能是292,366元、8,810,664元或226,970元。

## 保守式金額修復

部分PDF可能把數量的尾端與預算數黏成同一數字，例如原應為：

```text
數量：200
預算數：1,000
```

文字擷取後卻可能形成：

```text
預算數：51,000
```

新版工具在同一用途別科目發生「明細加總大於科目表列數」時，會執行保守式修復：

1. 只檢查單價空白且可能發生欄位黏連的明細。
2. 嘗試移除金額最左側1至3碼。
3. 以科目表列數作為約束。
4. 只有在找到**唯一組合**，且修復後明細可精確等於科目表列數時才採用。
5. 若沒有唯一解，維持原始擷取值並保留驗算警示。

工具不會靜默覆蓋原始資料。自動修復列會：

- 在畫面金額後標示 `*`。
- 以提示文字顯示原始擷取金額。
- 在XLSX匯出中保留「原始預算數」及「自動修復」欄位。
- 在「自動修復」工作表中列出修復前後金額、所屬計畫、科目、PDF頁碼及說明。

> 自動修復仍屬輔助機制，使用者應回查PDF原文。

## 四層加總驗算

工具使用同一份 `reconcile()` 函式執行畫面提示與回歸測試，避免UI與測試各自實作而產生規則漂移。

### 第一層：明細 → 用途別科目

同一用途別科目下的本年度明細合計，應等於該用途別科目的表列預算數。

下列層級不納入明細合計：

- 計畫說明
- 案別
- 總經費

### 第二層：用途別二級 → 用途別一級

依下列欄位組成分組key：

```text
工作計畫代碼｜分支計畫代碼｜用途別一級代碼
```

同一分支下重複出現的用途別一級科目，會先累加其表列數，再與其下用途別二級合計比較。

### 第三層：用途別一級 → 分支計畫

同一分支計畫下的用途別一級科目合計，應等於分支計畫金額。

### 第四層：分支計畫 → 工作計畫

同一工作計畫下的分支計畫合計，應等於工作計畫提要頁的預算金額。

若同一工作計畫分成經常門及資本門兩個提要頁，且代碼相同，工具會累加兩頁的工作計畫預算金額後再驗算。

## PDFium 後備引擎

部分地方政府PDF的內嵌字型無法由pdf.js正確解讀，可能出現 `g_font_error`，或表格內完全抽不到文字。

當pdf.js解析結果為0列時，工具會自動改用 `@embedpdf/pdfium`：

- JavaScript封裝採MIT授權。
- 底層PDFium採BSD-3-Clause授權。
- 只在需要時才從CDN動態下載。
- wasm gzip約2.0MB。
- 一般可由pdf.js處理的PDF不會載入PDFium。

PDFium字元流會轉換成接近pdf.js `getTextContent()`的資料形狀，再交由同一個 `parseLocalDoc()` 解析，因此兩個引擎共用相同的表格判讀、層級判別及驗算規則。

PDFium字元合併時採約14pt間距。此設定可能將右對齊金額尾端與說明欄第一個字合成同一文字run，但這與部分pdf.js文件本來就會產生的「預算數＋說明」黏連形式相同，會交由既有拆分規則處理。

### 臺北市政府社會局116年度案例

臺北市政府社會局116年度預算案包含大量跨年度連續性計畫、總工程費／總經費組成明細、工程分攤款、說明欄大型數字及少數欄位黏連情形，是本次修正的重要案例。

舊版解析結果出現22處「明細≠科目」警示，主要原因包括：

- 全期總工程費或總經費被當成本年度明細。
- 同一總經費標題與組成明細被重複計入。
- 說明欄大型數字誤入預算數欄。
- 少數數量、單價或預算數欄位發生黏連。

新版已加入對應規則，並以社會局PDF實際驗證：

- 本年度最底層明細共601筆。
- 本年度歲出明細合計為23,425,696,000元。
- 四層加總驗算為0處不符。
- 原22處差異已排除。
- `933,000,001` 已還原為本年度預算9,330,000元及案號 `01`。
- `780,800,002` 已還原為本年度預算7,808,000元及案號 `02`。
- 總工程費／總經費不再以紫色獨立列顯示，改由案別金額旁的紫色 `ⓘ` tooltip 呈現。

## 使用方式

### 線上使用

開啟GitHub Pages網站：

```text
https://cormort.github.io/local-budget-parser/
```

操作步驟：

1. 按「選擇檔案」。
2. 選取地方政府單位預算案PDF。
3. 按「解析」。
4. 等待進度完成。
5. 檢查四層加總驗算訊息。
6. 使用工作計畫、分支計畫、用途別科目、層級或說明關鍵字篩選。
7. 匯出XLSX、CSV、JSON或驗算差異。

- 預期的工作計畫、分支計畫、用途別科目及明細數量。
- 四層加總驗算為0處不符。

- 自動修復只在唯一解時發生。
- 自動修復保留原始預算數。
- 不得出現錯誤重建值 `933,000,001` 及 `780,800,002`。

## 已知限制

1. **只適用已支援的地方預算表格式**  
   本工具不是通用PDF表格擷取器。若章節名稱、欄位名稱或資料層級與實測格式差異過大，可能無法解析。

2. **掃描型PDF無法直接處理**  
   若PDF只有影像、沒有文字層，pdf.js與PDFium均無法直接取得表格文字。目前未整合OCR。

3. **高度客製化版面可能需要新增規則**  
   某些縣市或機關可能使用特殊欄寬、旋轉文字、合併欄位或其他產製系統。

4. **PDF文字座標可能存在誤差**  
   同一視覺列可能拆成多個文字物件，或不同欄位可能合成一個文字物件。

5. **自動修復不是原文證明**  
   金額修復只在唯一且可精確平衡科目表列數時執行，仍應人工回查PDF。

6. **四層驗算通過不代表所有文字完全正確**  
   金額加總為0處不符，只能證明已解析資料在目前層級間一致，不能證明說明文字、單位、數量或每一個欄位均與原PDF完全相同。

7. **CDN與網路限制**  
   pdf.js、SheetJS及PDFium由CDN載入。若使用環境封鎖外部CDN，需改為下載並以本機檔案引用。

8. **大型PDF效能取決於使用者裝置**  
   所有解析均在瀏覽器本機執行。頁數多、文字物件密集或裝置記憶體較少時，處理時間會增加。

## 工作計畫核對（歲出機關別預算表）

四層加總驗算是**自我一致性檢查**——最頂端的工作計畫預算數就取自歲出計畫說明提要表自己的表頭，
整條鏈沒有外部依據。同一本預算書的「**歲出機關別預算表**」以款項目節列出相同的工作計畫編號、
名稱與本年度預算數（千元），拿它比對才驗得到那個頂端數字。

### 版面差異（都已處理，皆為實測）

| 情形 | 例 | 處置 |
|---|---|---|
| 臺北市的表名不同 | 印成「歲出**預算表**」 | 標題改用 regex `/歲出(機關別)?預算表/` |
| 目次頁也含表名 | 高雄目次列「2.歲出機關別預算表 第 6頁至第 6頁」 | 含「目次」或「第N頁至第」的頁跳過 |
| 層級號與代碼黏成一個 item | 高雄 `01 　　　32020110101` | 取最後一段空白分隔的 token |
| PDFium 把三個年度金額併成一個 item | 新北 `"734,852 655,558 499,706 "` | 依空白拆開取第一段（欄序 本年度／上年度／前年度） |
| 名稱欄折行 | 新北 `新北市政府家庭暴`→`力暨性侵害防治中`→`心` | 往下吸收只有名稱欄文字的行 |
| 兩種列配置 | 地方版代碼與金額同列、名稱在下列；中央版代碼獨佔一列 | 兩種都吃 |

### 名稱比對是「不對稱」的

包含關係有方向，意義完全相反：

| 方向 | 意義 | 處置 |
|---|---|---|
| 機關別表名稱 ⊂ 本表名稱 | 機關別表被欄寬截斷 | 正常 |
| **本表名稱 ⊂ 機關別表名稱** | **本表這側名稱不完整＝解析漏字** | 報出來 |
| 兩邊互不包含 | 名稱對不上 | 報不符 |

用對稱的「任一方包含另一方」會把臺中 `導執行`（應為 `總預算編審與督導執行`）這種真錯誤放過去。

### 刻意不做的事

**「本表有、機關別表沒有」不視為錯誤。** 新北市有 7 個代碼含字母的工作計畫（`8970a010401` 等）
屬另一款別，本來就不列在這張表裡，報出來全是假警報。改為顯示涵蓋率（已核對 N/M 個）。

### 對不到的計畫會單獨提醒

「本表有、機關別表沒有」的計畫，其金額**沒有第二個來源可驗**——這不等於錯，但也不能吞進
「核對通過」裡，否則綠色的 ✅ 會被讀成「全部都驗過了」。故獨立以橘色區塊列出編號、名稱與金額，
明說「未經外部核對，請自行回對 PDF」，並提示代碼含字母者多屬另一款別、屬正常。
名稱欄抽不到文字而略過名稱比對者，同樣單獨提醒。

### 目前實測結果（七份範例）

| 來源 | 已核對 | 不符 | 無法核對 |
|---|---|---|---|
| 臺北市 | 4/4 | 0 | 0 |
| 臺中市 | 7/7 | 0 | 0 |
| 高雄市 | 4/4 | 0 | 0 |
| 新北市 | 4/11 | **1**（預算數） | 7 |
| 臺北市新工處 | 4/4 | 0 | 0 |
| 新北市社會局 | 14/15 | **4**（預算數） | 1 |
| 臺北市社會局 | 7/7 | 0 | 0 |

回歸測試把這三個數字都釘住（`agencyTable`），修好或再壞都會顯示出來。

**這道核對第一次跑就抓出 6 筆解析缺陷，已修**：工作計畫名稱印在代碼正下方且會折成多行，
原本只取其中一段，臺中 `導執行` 應為 `歲計會計業務-總預算編審與督導執行`、
臺北社會局 `全及平宅服務業務` 應為 `經濟安全及平宅服務業務`。修法見 `parseLocalDoc` 內的
「計畫名稱有兩種版面」註解——**必須分流**：代碼自成一個 item 時名稱在其下方（要往下接完），
代碼與欄位標籤黏在一起時名稱就在標籤行且完整；把前者的收集邏輯套到後者會一路吃進表格內文。

**剩下 5 筆「本年度預算數不符」尚未定案**：如新北社會局 `63111120301` 機關別表 2,014,999 千元、
本表 1,949,639 千元。已翻 PDF 確認機關別表側的抽取正確（第 24 頁原文即 2,014,999），
**但尚未判定是本表解析錯誤或兩表範圍不同**，需人工核對。
